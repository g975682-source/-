# engine3d: 신규 3D 선수 엔진

게임 본체와 분리된 신규 선수 모델 엔진입니다. 켜면 게임 선수가 새 3D 모델(스킨드 메시)로 그려지고, 끄거나 준비가
안 되었거나 불러오기에 실패하면 게임은 기존 절차 생성 모델로 그대로 돌아갑니다.

## 켜고 끄기

| 주소 | 동작 |
|---|---|
| `index.html?p3d=one` | 사람 팀 스트라이커 1명만 새 모델 |
| `index.html?p3d=team` | 사람 팀 11명 |
| `index.html?p3d=all` | 22명 전원 (기본값: 주소에 `p3d`가 없고 저장된 선택도 없을 때) |
| `index.html?p3d=0` | 끄기: 기존 절차 생성 선수 |

선택은 `localStorage` `gl-p3d`에 기억됩니다. `engine3d/` 폴더가 `index.html` 옆에 있어야 하고, HTTP로 열어야 합니다
(`file://`에서는 브라우저가 모델 파일 읽기를 막습니다). 예: `cd ground-legends && python3 -m http.server 8000` 후
`http://localhost:8000/index.html?p3d=one`.

## 구조

```
engine3d/
  player3d.js            엔진 (window.P3D): 모델 로딩, 선수별 복제와 유니폼 색, 게임 리그 → 모델 뼈 자세 옮기기
  models/mh_player.glb   선수 모델 (MakeHuman CC0, 손가락 포함 52뼈, 1.80 m); .glb.json은 같은 파일의 base64 (아티팩트용)
  anim/clips.json        모션 캡처 클립 8개 (CMU, 이 모델에 리타게팅), tools/bake_clips.js가 만듦
  tools/                 개발용 (웹사이트 사본에는 안 들어감): bake_clips.js, measure_loco.js, render_loco.js,
                         measure_match_motion.js, render_look.js
  vendor/GLTFLoader.js   three.js r128 examples (MIT)
  vendor/SkeletonUtils.js three.js r128 examples (MIT)
  LICENSES.md            자산별 라이선스
```

`index.html`에서 바뀐 곳은 세 군데입니다.

1. three.js 다음의 작은 로더: 켜져 있으면 위 세 파일을 받아 스크립트일 때만 실행하고 `P3D.init`을 부릅니다.
2. `renderVisuals`에서 선수들의 `applyVisual` 다음 한 줄: `if(window.P3D)P3D.frame(players,scene,teams,controlled);`
3. `applyVisual` 끝의 한 줄 `r.va=a;r.vspd=spd;`: 그 프레임에 그린 상태와 속도를 리그에 적어 둡니다(리플레이와 온라인
   게스트 화면에서도 맞는 값).

물리, 조작, AI, 온라인 메시지, 리플레이 기록은 바뀌지 않았습니다. 엔진은 게임이 그 프레임에 이미 계산한 리그 자세를
읽기만 합니다.

## 동작 방식 (1단계)

- 모델을 한 번 불러오고, 선택된 선수마다 `SkeletonUtils.clone`으로 복제합니다. 정점 색에 팀 유니폼(상의, 하의,
  양말), 선수의 피부·머리·축구화 색을 칠합니다. 골키퍼는 팀의 골키퍼 색입니다.
- 매 프레임 게임 리그 루트의 위치·방향·체형 크기를 복제본에 맞추고, 리그 관절 19개의 회전을 모델 뼈에 옮깁니다.
  게임의 모든 상태(달리기, 킥, 태클, 슬라이딩, 다이빙, 개인기, 세리머니)와 리플레이, 온라인 게스트 화면이 같은
  경로(`applyVisual`)를 거치므로 그대로 따라옵니다.
- 두 뼈대는 모두 쉬는 자세에 회전이 없고 +z가 정면, 왼쪽이 +x입니다. 쉬는 모양만 달라서(모델은 다리를 조금 벌리고
  팔이 A자) 팔다리 뼈마다 고정 보정을 넣어 게임 리그의 일자 기본 자세에 맞춥니다. 발은 모델 모양을 그대로 씁니다.
- 엉덩이 높이 = 게임의 엉덩이 비율(hipN/0.95) × 모델이 다리를 편 채 설 때의 높이. 경기 시작 자세에서 축구화
  가장 낮은 점은 −0.2 cm입니다.
- 게임의 기존 선수 메시는 카메라가 그리지 않는 레이어 1로 옮겨 숨깁니다. 리그 루트의 `visible`은 건드리지
  않습니다(온라인 동기화가 이 값을 보냅니다). 선수를 놓아주면 원래 레이어로 돌려놓습니다.

이 자세 옮기기는 기존 모델의 각도(발목, 킥 보정 포함)를 그대로 쓰므로 새 모델에 맞춘 동작은 아닙니다. 2단계부터는
서 있기·이동을 클립으로 바꾸고, 클립이 없는 상태(킥, 태클, 슬라이딩, 다이빙, 개인기, 세리머니 등)에만 이 방식을 씁니다.

## 동작 방식 (2단계: 서 있기·걷기·조깅·달리기)

- 클립: `tools/bake_clips.js`가 프로토타입의 `lab.js`·`retarget.js`를 그대로 써서 CMU 동작을 이 모델에 옮기고, 제자리
  클립(엉덩이 이동 제거)으로 30 fps JSON에 저장합니다. 게임은 BVH나 리타게팅 없이 이 JSON만 읽습니다.

  | 클립 | 원본 | 길이 | 자체 속도 |
  |---|---|---|---|
  | idle | 143_03 0.05–0.80 s | 0.75 s 반복 | 0 |
  | walk | 143_32 걷기 한 주기 (왼발 착지 사이, 자동 검출) | 0.78 s 반복 | 1.45 m/s |
  | jog | 16_35 조깅 한 주기 | 0.80 s 반복 | 2.84 m/s |
  | run | 143_01 | 0.72 s 반복 | 7.0 m/s |
  | start, decel, kick, recover | 143_03, 143_02, 143_24 | | 아직 안 씀 (3단계) |

- 게임 상태가 서 있기(0)나 달리기(1)이면 클립, 그 밖이면 자세 옮기기. 둘 사이는 0.12초 동안 섞습니다.
- 속도별 비중: 서 있기 → 걷기 0.25–0.9 m/s, 걷기 → 조깅 1.9–2.3, 조깅 → 달리기 4.6–5.2. 섞는 구간을 좁게 둔 것은 보폭이
  이웃끼리 2배 넘게 달라서 섞는 동안 디딤발이 미끄러지기 때문입니다.
- 걷기·조깅·달리기는 하나의 걸음 위상(왼발 착지 = 0)을 공유하고, 위상 속도는 게임 속도 ÷ 섞인 보폭이라 발이 땅과
  같은 속도로 움직입니다.
- 방향을 틀 때 회전 속도 × 이동 속도만큼 몸을 기울입니다(최대 0.3 rad, 부드럽게).
- 팔은 클립 대신 걸음 위상으로 그립니다. 모션 캡처의 팔·손목은 이 모델에 옮기면 가슴 앞으로 접히고 손목이 꺾여서입니다.
  기준은 보행·달리기 연구값입니다: 걷기는 팔꿈치를 거의 편 채(약 20°, 15–30° 움직임) 어깨를 앞뒤 20–25° 흔들고,
  달리기는 팔꿈치 약 90°(흔드는 동안 70–120°)로 손이 골반과 가슴 사이를 오가며 속도가 빠를수록 크고 높게 흔듭니다.
  손목은 중립. 같은 쪽 다리와 반대로 흔들고(왼발 착지 때 오른팔이 앞), 팔꿈치를 굽힐수록 위팔을 안쪽으로 돌려 앞으로
  흔든 손이 몸 중심선 쪽으로 옵니다. 속도별 값은 `player3d.js`의 `ARMK` 표.
- 손가락은 가볍게 쥔 주먹(손가락마다 그 방향에 수직인 축으로 굽힘, 엄지는 조금).

## 동작 방식 (3단계: 실제 축구 움직임, `MOVEMENT_ANALYSIS.md`)

- 방향 인식 이동: 그린 위치의 변화로 이동 방향을 구해, 엉덩이·다리를 이동 방향으로(최대 90°), 상체·목은 바라보는
  쪽으로 되돌림(최대 50°). 이동 방향이 몸 방향과 115° 넘게 다르면 뒷걸음(걷기·조깅 역재생, 100°에서 해제).
- 경합 자세: 견제(공을 보며 4.5 m 안의 상대 볼 보유자, 또는 사람의 견제 키), 볼 지키기, 어깨 경합(1 m 안에서 공을 다툼).
  `window.__game`의 공 소유와 선수 상태를 읽으므로 리플레이·온라인 게스트에서는 평소 자세.
- 브레이크·출발: 게임 속도의 변화로 급감속 때 낮추고 뒤로, 급가속 때 앞으로.
- 드리블: 상체 숙임, 팔 조금 벌림(걸음은 그대로).
- 킥(게임 상태 kick): CMU 킥 클립, 클립의 발 접촉(0.575 s)이 게임의 차는 순간(슛 visT 0.15, 패스는 첫 프레임)에 오게.
  왼발은 좌우 반전. 차는 발 반대 팔 벌림. 발리·헤딩·태클 등은 자세 옮기기 그대로.
- `index.html`의 `applyVisual`은 그린 상태·속도·위상·시간·방향을 리그에 적어 둡니다(`r.va, r.vspd, r.vph, r.vt, r.vside`).
- 게임 AI(`index.html`, 대형 유지와 마크): 실제 경기처럼 대부분 걷기·조깅, 필요할 때만 질주, 대형을 잡는 동안 공을 봄.
- 발 고정(IK): 클립으로 움직이는 동안 땅에 닿은 발 앞꿈치를 그 자리에 고정하고 다리를 두 관절 IK로 맞춤.
- 드리블: 게임의 공 터치 리듬(`touchPh`, 보폭마다 한 번)에 걸음 위상을 맞춤.
- 골키퍼 준비·헤딩·점프·태클: 게임 자세 위에 보정(`gamePoseFix`).
- 경합 자세는 그려진 위치와 그려진 공으로 판단하므로 리플레이·온라인 게스트에서도 나옴. `P3D.frame`의 다섯째 인자가 그려진 공.
- 클립 파일이 없으면 모든 상태가 1단계 방식으로 돌아갑니다.

디딤발 미끄러짐 (`tools/measure_loco.js`, 60 fps 고정 간격, 디딤발 평균 수평 속도):

| 게임 속도 | 0 | 1.4 | 2.1 (걷기+조깅) | 2.8 | 4.2 | 4.9 (조깅+달리기) | 5.5 | 7.0 | 8.5 m/s |
|---|---|---|---|---|---|---|---|---|---|
| 미끄러짐 | 0.02 | 0.52 | 0.45 | 0.24 | 0.32 | 1.15 | 0.27 | 0.27 | 0.34 m/s |

## 동작 방식 (4단계: 선수 외형)

게임이 선수마다 이미 가진 데이터(등번호·이름, 팀 유니폼, `bodyOf`의 체형, 머리 모양 `hs`, 수염 규칙)를 새 모델에도
그립니다. 모델 파일은 그대로이고, 모두 선수를 붙일 때 한 번 계산합니다.

- 등번호·이름: 등에 번호와 이름, 왼쪽 가슴에 작은 번호. 게임의 번호 그림(`rig.numMat`의 텍스처)을 그대로 씁니다.
  셔츠 표면에 맞춘 격자를 가까운 셔츠 정점 셋에 묶어 몸과 같이 스키닝하므로, 몸을 숙이거나 비틀어도 셔츠에 붙어 있습니다.
- 유니폼 무늬: 줄무늬(세로), 가로 줄(hoops), 가운데 띠(band)를 몸통에 셰이더로 그립니다(쉬는 자세의 위치 기준이라 경계가
  곧고 몸을 따라 움직임). 깃, 소매 끝, 양말 윗단은 팀의 trim 색.
- 골키퍼: 긴 소매(팔을 상의 색으로)와 장갑.
- 체형: 어깨·골반 너비(W)와 근육(M)을 모델의 쉬는 모양에 반영합니다. 몸통은 넓이·두께, 팔다리와 목은 뼈 둘레로 굵기,
  어깨 관절은 몸통 너비에 맞춰 바깥으로. 다리 관절과 발은 그대로라 걸음, 발 고정, 서 있는 높이는 바뀌지 않습니다.
- 머리: 머리선(이마는 높게, 관자놀이, 목덜미는 낮게; 귀는 제외)을 스타일별로 칠하고 두피에서 조금 띄웁니다.
  `hs` 0 보통, 1 짧은 머리(머리색과 피부색을 섞어 짧게 깎은 느낌), 2 묶은 머리(뒤통수 위에 번).
- 수염: 게임과 같은 규칙(이름 해시 % 3 = 0, 약 3명 중 1명). 코 아래 얼굴 앞과 턱선.
- 선수 한 명을 꾸미는 데 약 7–8 ms(SwiftShader)라, 한 프레임에 12 ms까지만 붙이고 나머지는 다음 프레임에 붙입니다.
  그동안은 게임 기본 모델로 보입니다.

`tools/render_look.js`: 앞·뒤 모습, `HEAD=1` 얼굴 가까이, `BUILD=1` 체형 양 끝, `HOMETEAM`/`AWAY`로 팀 선택.

## 확인

`node ground-legends/tests/p3d_smoke.js`: 엔진 꺼짐·기본값, 1명 표시와 위치·방향·지면, 클립 로딩, 방향키로 달릴 때 클립
재생, 슛 때 킥 자세 전환, 모델 파일 없음·HTML 응답·`.json` 대체, 22명 표시와 처리 시간. `P3D_SITE=docs`로 웹사이트 사본. 결과 예: 22명일 때 엔진 CPU 시간 약 0.8 ms/프레임, 선수 1명 준비 약 2 ms
(SwiftShader, 스키닝은 GPU).

## 아직 없는 것

- 얼굴 생김새 차이(모델 얼굴 하나를 모두 씀), 긴 머리 같은 머리 모양 메시
- 무늬의 소매 연장, 셔츠·피부 경계(모델의 정점 단위라 깃 부분이 들쭉날쭉)
- 공과 발의 실제 접촉(공이 발 앞 0.6–0.9 m에 있음)
- 경사·지면 접촉 보정
