# 선수 모델·애니메이션 자산 확보 — 조사와 프로토타입

게임 본체(`ground-legends/index.html`, `docs/index.html`)와 분리된 실험입니다. 게임 본체, 물리, 조작, AI,
온라인 동기화, 리플레이, 클럽 시스템은 바꾸지 않았습니다. 게임은 슛 장면을 기록하려고 **읽기 전용**으로만
불러왔습니다. 위의 상위 폴더(`glb-viewer/`)에 있던 파일과 결과는 그대로 두었습니다. `retarget.js`와
`vendor/*.js`는 고치지 않고 불러서 씁니다.

결과 수치는 모두 이 작업 환경에서 `node check_player.js`를 실행해 얻었습니다(2026-10-28, 게이트 1261개).
표는 `out/check_player_tables.md`, 게이트 하나하나는 `out/check_player_gates.log`에 있습니다.

### 이번에 손본 것(이유와 함께)

1. **쇄골**: `retarget.js`는 각 뼈가 원본과 같은 방향을 가리키게 옮깁니다. 그런데 cgspeed T자세의 쇄골은
   34° 위를 향하고, MakeHuman A자세의 쇄골은 25° 아래를 향합니다. 그대로 옮기면 어깨가 약 56° 솟아서
   메시가 부풀었습니다. 그래서 쇄골은 가슴에 붙은 기본자세로 두고, 그 회전을 위팔 트랙에 넘겨 팔 방향은
   원본과 같게 했습니다(`lab.js` clavicleRelative). 어깨를 으쓱하는 동작은 옮겨지지 않습니다.
   `retarget.js` 자체는 수정하지 않았습니다.
2. **제자리 클립의 이동 경로**: `retarget.js`의 제자리판은 이동 경로를 ±0.25 s 이동 평균으로 구하는데,
   클립 끝에서 창이 잘립니다. 그래서 클립 양 끝에 이동이 남습니다(143_01이 4.75 m/s로 보임. 실제는 6.9 m/s).
   `lab.js`는 앞뒤로 0.35 s를 더 리타깃해 경로를 구한 뒤 잘라냅니다. 테이크 자체가 끝나는 곳에서는 창을
   양쪽으로 함께 줄입니다. 143_02는 첫 프레임부터 달리고 있어서, 한쪽만 줄이면 몸이 0.71 m 앞서 나갔습니다.
3. **전환 시점과 위상**: 달리기 → 감속은 다음 한 주기 안에서 두 클립의 자세가 가장 비슷한 순간과 감속 위상을
   골라 전환합니다(속도 차 1.5 m/s 이내). 처음에는 속도만 맞췄는데, 이때 발이 1.3 m 미끄러졌습니다.
   킥과 회복은 한 번의 리타깃에서 잘라 0.15 s 겹치게 했고, 같은 테이크 시각끼리 섞습니다.
4. **크로스페이드**: three.js의 `fadeOut`은 항상 가중치 1에서 시작합니다. 그래서 페이드 중에 다른 페이드가
   끼어들면 가중치가 튑니다. `lab.js`는 각 클립의 현재 가중치에서 선형으로 줄입니다. 상태 재시작(킥 → 킥)용으로
   클립 사본을 하나 더 둡니다.

**하지 않은 것**: 킥 중 공 접촉을 맞추려는 위치·방향 보정은 하지 않았습니다. 발 IK, 지면 보정, 몸 회전 보정도
없습니다. 킥은 접촉 추정 시각이 게임의 접촉 틱에 오도록 **시작 시각/위상만** 고릅니다. 위치와 방향은
그대로 측정했습니다.

## 4. 호환성과 성능 (측정값)

- **three.js r128**: GLTFLoader 로드, 스킨, 바인드 행렬을 확인했습니다(`check`: Mixamo 22개 이름과 부모 관계 정상,
  가중치 합 오차 0, 역바인드 행렬 오차 5.9e-8, 발이 y=0, 정면 +z, 왼쪽 +x). 파일에 클립은 없습니다.
- **Player.step(믹서 갱신 + 페이드 2층)**: 52뼈 28.7 µs, 22뼈 12.6 µs. 이 컨테이너의 CPU에서 2,000회 평균이고,
  선수 22명이면 0.63 ms / 0.28 ms입니다.
  - 클립 묶음 리타깃: 0.27–0.39 s(로드할 때 한 번).
  - **렌더링 fps는 측정하지 않았습니다**(SwiftShader에서는 의미가 없음). 정점 13,380개 × 22명 = 29만 정점의 GPU
    스키닝이 모바일에서 감당되는지는 미확인입니다.
- **게임과의 연결**: 게임 슛을 읽기 전용으로 기록했습니다. 프레스 1 s 전부터 180틱까지 기록했고, 장면은
  서서·직선 달리기·대각 달리기 × D 0.1/0.2/0.3 s, 그리고 달리다 차고 멈추기 2개입니다. 그 선수 위치와 방향을
  홀더에 그대로 쓰고 클립은 제자리로 틀었습니다.
  - 게임은 달리다 슛하면 접촉 때 2.36 m/s로 느려집니다.
  - 대각 달리기에서는 공이 선수 정면에서 약 36° 옆으로 나갑니다(접촉 때 선수 방향은 바뀌지 않음).

## 5. 추천

- **추천: A (MakeHuman CC0 선수 + CMU 피험자 143 이동 + 143_24 킥)**.
  - 라이선스: 둘 다 상업 사용 가능으로 확인했습니다. CMU 현재 문구는 미확인입니다.
  - 한 배우의 동작이라 체형과 자세가 이어집니다.
  - 서서 차는 킥과 직선 달리기 킥은 게임의 접촉 틱에서 공 위치·타이밍·방향 기준을 보정 없이 통과했습니다.
    다만 공이 선수 앞 0.5 m에 놓이는 것은 이 테이크에 우연히 맞은 결과입니다.
- **차선: B의 10_01 (같은 모델·이동 + 피험자 10 킥)**.
  - 지면 관통이 가장 작습니다(체인 −1.9 cm, 통과).
  - 킥 뒤 앞으로 감속하며 멈춰서, 회복이 143_24보다 자연스럽습니다.
  - 다만 제자리 재생에서는 발이 공보다 0.42 m 앞에서 차고 지나가, 접촉 기준을 통과하지 못합니다.
- **최종 판정: A는 "서서 차기와 상태 체인" 범위에서만 최소 검증을 통과했습니다.** 달리며 차기, 대각 차기, 지면
  접촉은 통과하지 못해 게임 통합 후보로는 아직 부족합니다. 종료 조건 B에 해당하는 부분으로, 더 필요한 자산은
  아래와 같습니다.
  1. **달리며 차는 오른발 킥**: 게임 속도(접근 5.5 m/s, 접촉 2.4 m/s)의 모션 캡처. CMU의 킥 7개는 모두 접근
     1.5–3.7 m/s의 2~3걸음 킥이라, 게임 위치에서 제자리로 틀면 디딤발이 0.1–0.36 m 밀립니다.
  2. **대각 킥**: 달리는 방향에서 30–40° 옆으로 차거나, 돌면서 차는 동작. 게임은 이 각도로 공을 보냅니다.
  3. **앞으로 이어지는 회복**: 143_24는 킥 뒤 0.7 m/s로 뒤로 물러납니다.
  4. **같은 배우(143)의 공 몰기 달리기와 6 m/s 이상에서의 감속**: 143_02는 약 6 m/s에서 시작합니다.
  5. 위 자산이 없으면 발 IK와 지면 접촉 보정이 필요합니다. 이는 새 기술이라 별도 승인이 필요하며, 이번에는
     하지 않았습니다.
  - C(Quaternius, CC0로 알려짐)와 D(Mixamo)는 1·2에 해당하는 동작이 있을 수 있습니다. 그러나 이 환경에서 받을
    수도, 라이선스를 확인할 수도 없어 미확인입니다.

## 6. 실행 방법

```
cd ground-legends/prototypes/glb-viewer/player-animation
python3 build_player.py                    # out/mh_player.glb (+ --no-fingers 로 22뼈 판)
node check_player.js                       # 약 2분: 게임 기록, 킥 7종 × 13장면, 게이트, 표, 스크린샷
node check_player.js --kicks 143_24 --no-shots   # 한 후보만, 15초
```

- 뷰어는 `glb-viewer/` 폴더를 정적 서버로 열고 `player-animation/index.html`을 엽니다. 예:
  `python3 -m http.server -d ground-legends/prototypes/glb-viewer 8000` →
  `http://localhost:8000/player-animation/index.html`. three.js는 cdnjs r128에서 받습니다.
- 뷰어에서 할 수 있는 것:
  - 클립 ▶ 버튼, 속도 배율, 시작 위상, 크로스페이드 길이, 루트 모션 켜기/끄기
  - 체인 재생, 반복 킥
  - 게임 슛 장면 재생(`out/game_probe.json`이 있을 때)
  - 발 궤적: 초록 = 땅에 정지, 빨강 = 땅에서 미끄러짐, 파랑 = 공중
  - HUD: 발 높이, 관통, 미끄럼 속도
- Playwright와 three r128의 경로는 `tests/legacy/paths.js`를 따릅니다.
