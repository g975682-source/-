## 4. 리타깃 파이프라인과 실행 방법

- **만들지 않았습니다.** 아래는 자산이 확보되면 진행할 설계입니다(미구현, 미검증).
- 새 디렉터리 `player-animation/stage3/` 아래에서 다음 순서로 진행합니다.
  1. **원본 보관**: 원본은 `stage3/raw/<출처>/`(gitignore)에, 라이선스 원문은 `stage3/licenses/`에 두고, 원본의 SHA-256을 기록합니다. 변환 결과는 `out/stage3/`에 따로 둡니다.
  2. **로더**: three r128 `examples/js/loaders/FBXLoader.js`(+`fflate`)를 씁니다. MIT 라이선스이며, 이 환경의 기존 의존성 폴더에 0.128.0판이 있는 것을 확인했습니다(아직 복사하지 않음).
  3. **원본 확인**: 뼈 이름 목록, 좌우 표기, 위쪽 축(FBX는 Y-up/Z-up 둘 다 가능), 단위(cm면 ×0.01), 스케일, 바인드 자세(T/A)를 클립마다 확인해 JSON으로 남깁니다.
  4. **리타깃**: `retarget.js`는 원본의 프레임 0을 기본 자세로 가정하는 CMU 전용입니다. 그래서 바인드 자세를 기준으로 하는 새 파일(`stage3/retarget_fbx.js`)과 이름 대응표(Mixamo / UE5 Manny / Rokoko / CC)를 작성합니다. 쇄골을 다루는 방식은 1차에서 찾은 것을 따릅니다.
  5. **같은 조건에서 비교**: 기존 게임 기록(`out/game_probe.json`)과 같은 장면·같은 게이트로 기준선과 비교합니다(`check_player.js --probe out/game_probe.json`). 새 클립 묶음은 `--variant` 방식처럼 별도 파일로 주입하고, 52뼈·22뼈 모델 둘 다 돌립니다.
  6. **원본 직접 재생**: 원본 모델로 원본 동작을 재생한 결과와 우리 모델의 결과를 같은 조건에서 나란히 비교합니다(프레임 시트).
